# Генератор «Акта приёмки ТМЦ» (РИТЕТ)

Собирает акт приёмки по импортной поставке из первичных документов за секунды:
кладёте файлы в папку → одна команда → готовый `.xlsx` по фирменному шаблону.

## Что умеет
| Источник | Что берётся | Куда ложится в акте |
|---|---|---|
| Инвойс поставщика (PDF, Cetinkaya Pano / EMAS) | номер, дата, все строки (артикул, кол-во, цена), итог EUR. Скан EMAS — только через браузерный мастер (OCR) | шапка, F19, база для этапов 2 и 4 |
| Счета КВТ Сервис (PDF, сколько угодно) | номер, дата, валюта, сумма, НДС; **авто-классификация**: доставка до границы / РФ+брокер (в т.ч. хранение, СВХ, линейный сбор, брокер, перевозка по РФ) / ПРР | раздел 6, строка «рубли» (G72 / I72 / K72) |
| ГТД / ДТ (PDF) | номер, дата ТО, курс EUR (гр. 23), сбор 1010 / пошлина 2010 / НДС 5010 (раздел B) | M72 / O72 / Q72, U79, дата ТО F16 |
| Упаковочный лист (PDF: Inseda / EMAS по коробкам) | паллеты, коробки, объём, брутто, нетто, шт; EMAS — ещё и кол-во по артикулам | строка B12, этап 1 |
| Пакинг «факт» (XLSX) | фактически пришедшее кол-во по артикулам | этап 2: расхождения план/факт, ∆, сумма, пометка |
| Заказ поставщику (XLSX) | кол-во в заказе | этап 4 (справочно) |
| `params.json` | № акта, даты, курсы, ответственные, ручные добавки | шапка, подписи, недостающие документы |

Счета в USD пересчитываются в рубли по курсу ЦБ на дату ТО (курс задаётся в `params.json`,
т.к. сайт ЦБ из этой среды недоступен; при доступе к сети берётся автоматически).
Формулы шаблона (∆, итоги, % от инвойса, кросс-курс) сохраняются — Excel пересчитает при открытии.

## Использование
```bash
python3 akt.py cases/<папка_поставки>            # результат рядом: «Акт приёмки №N (…).xlsx» + summary.json
python3 akt.py cases/<папка> --out ~/акт.xlsx     # или указать файл
```
Имена файлов не важны — тип документа определяется по содержимому.

## params.json (пример)
```json
{"act_no": "1", "label": "СР отгрузка 1 в 26",
 "pickup_date": "17.07.2026", "depart_date": "", "to_date": "24.08.2026", "arrival_date": "",
 "usd_rate": 82.9211, "eur_rate": 96.8601,
 "responsible": "Макеева И.В.",
 "extra_costs": [{"number": "1043", "currency": "USD", "total": 2050, "category": "border"}],
 "customs": {"number": "10131010/240826/5298969", "date": "24.08.2026", "fee": 73860, "duty": 176989.31, "vat": 656100.41},
 "fact_overrides": {"CP1043Y": 12, "CP6901": 77}}
```
- `extra_costs` — счета, которых нет в папке PDF (категории: `border`, `rf_broker`, `prr`).
- `customs` — платежи по ГТД вручную, если PDF ГТД не приложен (при наличии PDF игнорируется).
- `fact_overrides` — факт только по расхождениям (остальные артикулы = инвойсу); при наличии пакинг-XLSX не нужен.

## Печатная форма (PDF по стандарту акта)
```bash
python3 render.py "cases/<папка>/Акт приёмки №N (…).xlsx" [папка_вывода]
```
Собирает из xlsx точную печатную копию (A4 альбомный, один лист, как образец): объединения, рамки,
шрифты и ширины из шаблона, формулы просчитаны, скрытые строки не печатаются. Выход: `.pdf` и `.png`.
Нужен Chromium из Playwright (в этой среде уже есть); LibreOffice не требуется.

## Обработка для менеджера (без установки чего-либо)
`app/Акт приёмки — мастер.html` — один файл, скачать и открыть двойным кликом в Chrome / Edge / Яндекс.Браузере.
Работает офлайн, файлы никуда не отправляются. 8 шагов: инвойс → счета КВТ (можно все сразу, категорию
можно поправить в списке, недостающий счёт добавить вручную) → ГТД → упаковочный лист → факт (XLSX) →
документ 1С «Приобретение» (XLSX) → реквизиты и даты → итог. На последнем шаге: «Скачать акт (xlsx)»
(заполненный фирменный шаблон), «Печатная форма» (A4 альбомный, один лист) и `summary.json`.
Результат совпадает с `akt.py` по всем ячейкам (проверено на CP-1-2026).

**Сканы (инвойс EMAS).** Если у PDF нет текстового слоя, мастер распознаёт его сам (tesseract встроен в файл,
интернет не нужен): выравнивает скан, находит линии таблицы и читает каждую ячейку отдельно, проверяя
«кол-во × цена = сумма». Строки, где проверка не сошлась, показываются с картинкой для ручной правки;
артикулы уточняются по упаковочному листу / факту (OCR путает O/0, I/1). Несколько инвойсов — загрузить все,
строки объединяются. Упаковочный лист EMAS (по коробкам, «Coli No») читается полностью: коробки, паллеты,
объём, вес, контейнер и количества по артикулам → этап 1 акта (упаковочный лист vs инвойс).

Сборка после правок: `python3 app/build.py` (собирает `src.html` + `vendor/*` + `template.xlsx` в один файл);
проверка: `node app/test.cjs` (Playwright, прогоняет все 8 шагов и скачивает акт).

## Файлы
- `app/` — браузерная обработка: `src.html` + `src_ocr.js` (исходники), `build.py`, `vendor/` (pdf.js 3.11, ExcelJS 4.4, fflate 0.8, tesseract.js 6 + eng), готовый `Акт приёмки — мастер.html` (~15 МБ)
- `akt.py` — генератор (Python 3, зависимости: `pymupdf`, `openpyxl`)
- `render.py` — печатная форма xlsx → PDF/PNG (Chromium через Playwright)
- `template.xlsx` — фирменный шаблон акта (с Google Диска, «Акт приёмки Шаблон.xlsx»)
- `cases/CP-1-2026/` — пример: отгрузка Cetinkaya Pano №1 2026 (инвойс CTI2026000000504)

пошлина 176 989,31 ₽ · НДС 656 100,41 ₽; этап 2 — 8 расхождений, итог −155,25 €.
